# 第一章 环境与常见坑

> [!info] 本章解决什么
>
> 代码本身没写错却跑不出结果，多数时候问题出在环境：工作目录不对、文件编码不对、包没加载、图形设备不支持中文。本章把这些坑集中列一遍，后面各章不再重复。

## 一、R 的位置与运行方式

本机的 R 装在 `E:\R\R-4.6.1`，命令行解释器是：

```text
E:\R\R-4.6.1\bin\x64\Rscript.exe
```

在 VSCode 里通常有两种跑法。一种是把光标放在脚本里逐行执行（借助 R 扩展的终端），适合边写边看；另一种是在终端里整段运行脚本，适合确认"从零跑一遍能不能过"：

```text
& "E:\R\R-4.6.1\bin\x64\Rscript.exe" --vanilla hw2.R
```

`--vanilla` 表示不读取 `.Rprofile`、不恢复上次的工作区。批处理脚本加这个参数，能避免"我这里能跑、换台机器就不行"的差异。

## 二、工作目录

R 读文件时，相对路径是相对**工作目录**（working directory）解析的，不是相对脚本文件所在目录。这一点和 Python 的习惯不同，是"文件明明存在却读不到"的头号原因。

```r
getwd()
#> [1] "E:/SUFE/junior/term1/高维数据分析"
```

`getwd()` 给出当前目录。切换目录用 `setwd()`，但更稳妥的做法是**不要用 `setwd()`**，而是让工作目录在启动时就固定在工作区根目录：VSCode 用"打开文件夹"打开 `高维数据分析`，RStudio 则新建 Project。这样所有脚本里的相对路径都一致，换机器也不用改代码。

拼接路径用 `file.path()`，它会按平台补分隔符：

```r
data_dir <- file.path("hw2@1029-2200", "hw2-2026-data")
list.files(data_dir)
#> [1] "ais.csv"       "ais_split.csv" "lakemary.csv"  "salary.csv"    "turkey.csv"    "wblake.csv"
```

> [!warning] 路径写法
>
> Windows 的路径分隔符是反斜杠，但 R 字符串里 `\` 是转义符。写 `"C:\data\a.csv"` 会报错，要么写成 `"C:/data/a.csv"`，要么写 `"C:\\data\\a.csv"`，要么用 `file.path()`。此外 R 区分大小写，`Boston.csv` 与 `boston.csv` 是两个文件；Windows 资源管理器默认隐藏扩展名，容易把 `data.csv.txt` 当成 `data.csv`。

## 三、中文与编码

本机 R 的本地编码是 UTF-8：

```r
Sys.getlocale("LC_CTYPE")
#> [1] "Chinese (Simplified)_China.utf8"
```

UTF-8 是 R 会话内部的统一编码。麻烦出在**外部文件**：课程群里下载的 CSV 可能是 GBK（Excel 在中文 Windows 下"另存为 CSV"的默认编码），直接读进来就会乱码。`read.csv()` 的 `fileEncoding` 参数负责在读入时转换编码：

```r
csv_path <- file.path(tempdir(), "gbk_demo.csv")
demo <- data.frame(city = c("上海", "北京"), score = c(88, 92))
write.csv(demo, csv_path, row.names = FALSE, fileEncoding = "GBK")

ok <- read.csv(csv_path, fileEncoding = "GBK")
ok
#>   city score
#> 1 上海    88
#> 2 北京    92
identical(ok$city, c("上海", "北京"))
#> [1] TRUE
```

如果文件是 UTF-8 带 BOM（Excel 另存为"CSV UTF-8"时常见），读进来第一列名会多出 `\ufeff`，表现为"列名对不上"。此时改用 `fileEncoding = "UTF-8-BOM"`。

排查乱码的顺序是：先用文本编辑器确认文件真实编码，再用 `fileEncoding` 指定它，最后用 `Encoding()` 检查读入结果。不要反过来靠 `iconv()` 反复试，那样容易把已经正确的字符串二次转换。

## 四、扩展包

`library()` 把包加载进当前会话，`require()` 功能相同但返回逻辑值、失败时不报错，脚本里用 `library()` 更安全：包不存在时立刻停下，而不是带着缺失的函数继续跑。

```r
library(alr4)
ds <- data(package = "alr4")$results[, "Item"]
length(ds)
#> [1] 80
sort(ds)[1:5]
#> [1] "ais"      "allshoots" "baeskel"  "BGSall"   "BGSboys"
```

包与包之间会出现同名函数，后加载的覆盖先加载的，这叫**掩码**（masking）。典型例子是 `dplyr::filter` 覆盖 `stats::filter`，`dplyr::lag` 覆盖 `stats::lag`。加载时 R 会打印一行 `The following objects are masked from ...`，那行提示值得看一眼。要确保调用的是某个包里的版本，用双冒号显式指定：`stats::filter()`、`dplyr::filter()`。

查看已装的包与版本：

```r
ip <- installed.packages()[, c("Package", "Version")]
ip[ip[, "Package"] %in% c("alr4", "car", "MASS"), ]
#>      Package Version 
#> alr4 "alr4"   "1.0.7" 
#> car  "car"    "3.1-5" 
#> MASS "MASS"   "7.3-65"
```

版本号以本机实际安装为准，上面的数字仅作格式示例。`sessionInfo()` 会一次列出 R 版本、平台和全部已加载的包，写作业报告时附上它，结果更容易复现。

`alr4` 自带教材的 80 个数据集，加载包后可以直接按名字使用，不需要 `read.csv()`：

head(UN11, 3)

#> Algeria     Africa africa     2.142 4473.0    75.00       67
str(UN11)
#> 'data.frame':	199 obs. of  6 variables:

注意 `UN11` 的 199 行是**删去缺失值之后**的结果，原始数据更多；`str()` 末尾的 `na.action` 属性记录了被删掉的行号。这也是读 `str()` 的价值：它在几行里同时交代了维度、列名、类型、因子水平，以及这类容易忽略的属性。

`Wool` 是个例外：它不在 `alr4` 的数据索引里，而是随 `car` 的依赖 `carData` 一起加载，所以加载 `alr4` 后同样能直接用。若换到没有加载 `car` 的环境，写成 `carData::Wool` 更稳妥。

```r
dim(Wool)
#> [1] 27  4
names(Wool)
#> [1] "len"    "amp"    "load"   "cycles"
```

> [!tip] 把课程数据存成 CSV
>
> 作业里若需要提交数据文件或与 Python 交换，用 `write.csv(UN11, "UN11.csv", row.names = FALSE)`。写回时加 `row.names = FALSE`，否则会多出一列没有列名的行号，再读进来时列数对不上。

## 六、工作区与文件保存

退出 R 时若选择保存工作区，会生成 `.RData`，下次启动自动恢复所有对象。这在初学阶段是负担：上次留下的变量会悄悄影响这次的结果，而且报错信息指向一个早已不存在的对象。建议不保存工作区，需要留存的对象显式保存。

```r
fit_path <- file.path(tempdir(), "fit.rds")
saveRDS(lm(mpg ~ wt, data = mtcars), fit_path)
fit <- readRDS(fit_path)
class(fit)
#> [1] "lm"
```

`saveRDS()` 与 `readRDS()` 一次只存一个对象，读回时可以随便命名，是推荐方式。`save()` 与 `load()` 保存的是对象名本身，读回时会直接覆盖同名变量，容易造成冲突。`save.image()` 等价于退出时保存工作区，不建议在脚本里调用。

另外，脚本目录里出现的 `Rplots.pdf` 是 R 在没有图形窗口时把图写到了默认设备，属于副产物，不是错误；用 `dev.off()` 正常关闭设备，或用显式的 `png()`/`pdf()` 就不会产生它。

## 七、图形设备与中文显示

这一节是实测结论，不是通用建议。在本机 R 4.6.1 上，默认的 `png()` 设备能正常显示中文；而默认的 `pdf()` 会丢失中文，图上出现 `..`，同时给出 `conversion failure ... in 'mbcsToSbcs'` 的警告。可用的写法有三种：

```r
# 1. 默认 png 设备，直接可用
png(file.path(tempdir(), "a.png"), width = 800, height = 600)
plot(1:5, main = "中文标题", xlab = "横轴", ylab = "纵轴")
dev.off()

# 2. pdf 指定 GB1 字体族
pdf(file.path(tempdir(), "b.pdf"), width = 6, height = 4, family = "GB1")
plot(1:5, main = "中文标题", xlab = "横轴")
dev.off()

# 3. cairo 设备指定系统中文字体
cairo_pdf(file.path(tempdir(), "c.pdf"), width = 6, height = 4, family = "SimSun")
plot(1:5, main = "中文标题", xlab = "横轴")
dev.off()
```

反过来，`png(type = "cairo")` 在不指定字体时会把中文画成方框，需要加 `family = "SimSun"`。规律是：**Windows 默认设备用系统字体，cairo 设备要自己点名中文字体**。图形参数在 [[09-绘图]] 另有展开。

## 八、常见坑速查

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| 读文件报 `cannot open file` | 工作目录不对，或路径用了反斜杠 | `getwd()` 确认位置；路径用 `/` 或 `file.path()` |
| 中文变成 `锟斤拷`、`?` | 文件是 GBK，未指定编码 | `read.csv(..., fileEncoding = "GBK")` |
| 列名前面多一个怪字符 | UTF-8 BOM | `fileEncoding = "UTF-8-BOM"` |
| `could not find function` | 包没 `library()`，或函数名拼错 | 加载包；`??函数名` 搜帮助 |
| 同名函数行为不对 | 被后加载的包掩码 | 用 `包名::函数名()` |
| 找不到 `UN11` | `alr4` 未加载 | `library(alr4)` 或 `data("UN11", package = "alr4")` |
| 图里中文是方框 | PDF/cairo 设备没配中文字体 | 用默认 `png()`，或 `family = "GB1"` / `"SimSun"` |
| 多出一列 `X` 或行号错位 | 写 CSV 时保留了行名 | `write.csv(..., row.names = FALSE)` |
| 上次的变量干扰本次结果 | 恢复了 `.RData` | 启动加 `--vanilla`，或退出时不保存工作区 |
